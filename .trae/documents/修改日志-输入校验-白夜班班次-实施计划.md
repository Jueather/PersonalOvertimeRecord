# 修改日志 + 输入校验 + 白夜班班次记录 实施计划

## Context（背景）

用户提出三项需求：
1. **修改日志**：设置页加"修改日志"入口，弹窗展示各版本更新内容（内置 APK 离线可看），仓库根目录维护 `CHANGELOG.md` 源文件
2. **白夜班班次**：每条记录可标记 白班/夜班（默认白班），录入对话框可切换，列表与月统计中展示/区分；**不改变工资计算规则**
3. **输入校验**：录入表单改用已有的 `DataValidator`（目前全项目零调用）；同步/导入恢复时做字段级校验，非法记录跳过并计数

**顺带修复的既有 bug**：[SyncManager.kt](file:///d:/Android/AndroidStudioProjects/PersonalOvertimeRecord/app/src/main/java/com/example/personalovertimerecord/utils/SyncManager.kt#L519-L537) 私有 `toBackup()` 漏拷 `customRate`，WebDAV 上传后自定义倍率丢失。本次将三处 `toBackup` 收敛为一份共享实现。

**硬约束**：
- `AttendanceEntityBackup` 字段声明序影响 checksum；PC 端 `pc-monitor/overtime_monitor.py` 按 JSON 键序复刻 Gson 序列化——新字段用**可空 String** 时 PC 端 checksum 逻辑零改动，仅需更新展示/统计
- Room 升级 v7→v8 必须写迁移；`app/schemas/` 自动生成的 8.json 需随代码提交

### 0.1 类型决策
- 序列化用**可空 String**（`"DAY"`/`"NIGHT"`）：Gson 缺字段为 null 自动兼容旧备份（同 `customRate` 模式）；PC 端按键序遍历自动兼容
- [OvertimeModels.kt](file:///d:/Android/AndroidStudioProjects/PersonalOvertimeRecord/app/src/main/java/com/example/personalovertimerecord/data/OvertimeModels.kt) 新增枚举（仅 UI/转换层用，不直接序列化）：

```kotlin
enum class ShiftType(val displayName: String) {
    DAY("白班"), NIGHT("夜班");
    companion object {
        /** 非法/未知值兜底为白班，不阻断恢复 */
        fun fromStringOrDefault(value: String?): ShiftType =
            entries.find { it.name == value } ?: DAY
    }
}
```

## 阶段 3：同步/恢复字段级校验

### 3.1 `DataExporter.kt` 新增私有纯函数 `validateBackupRecord(r): List<String>`
校验项：date 格式+年月日范围（allowFuture=true）、`manualOvertimeHours/manualExtraHours ∈ {-1}∪[0,24]`、`leaveHours ∈ [0, 24*31]`、`customRate == null || [1.0,4.0]`、`leaveType` 可解析、打卡时间格式。**shiftType 非法不判非法**，走 `fromStringOrDefault` 兜底 + `AppLogger.w`（展示性字段不值得丢整条记录）。

### 3.2 恢复路径接入
- `restoreDataFull()`：整包可信语义——含非法记录则抛异常中止（错误带非法条数+首条原因），与现行 `validateForFullRestore` 保护哲学一致（空日期/重复日期检查并入）
- `restoreDataIncremental()`：非法记录 `invalid++; AppLogger.w; continue`（扩充现有 `date.isBlank()` 跳过分支）
- `SyncSummary` 加 `val invalid: Int = 0`，`toDisplayString()` 加"非法跳过 N 条"
- `SyncManager.downloadAndRestore` 把 invalid 透传进 `SyncReport`（`SyncModels.kt` 加 `invalidCount`，`toSummaryString()` 展示）
- `TeamSyncManager.applyServerState()` 落库前过同一校验器，计数进 `TeamSyncReport`

## 端到端验证

```powershell
gradlew.bat :app:assembleDebug
gradlew.bat :app:testDebugUnitTest
cd server && gradlew.bat build
python pc-monitor\overtime_monitor.py   # 观察自测输出与监控页
```

自测场景：
1. v7 库升级安装 → 启动正常、老记录完整（MIGRATION_7_8 + schema 8.json 已提交）
2. 添加记录切"夜班" → 列表夜班角标、统计显示"白班 Xh · 夜班 Yh"、工资总额不变
3. 编辑老记录 → 默认白班；同步上传下载往返班次不丢
4. WebDAV 双向同步含夜班记录 → 云端 JSON 含 `"shiftType":"NIGHT"`、checksum ok；PC 监控 checksum ok、明细带夜班标签
5. 构造含非法记录的备份（日期 `2026-13-40`、时长 99h、shiftType `"XXX"`）→ 增量恢复非法 2 条跳过并计数、班次非法按白班入库
6. 团队同步：服务端 upsert 后 `shift_type` 有值，管理端汇总不受影响
7. 设置页"修改日志"→ 离线弹窗展示 CHANGELOG 全文
8. 对话框校验：加班填 12h → 拦截；未来日期 → 拦截（新增）

**风险点**：
- 旧版 App 读新备份：Gson 忽略未知字段，天然兼容；新版读旧备份：可空 String 兜底
- 三处 `toBackup` 必须合并，否则每次加字段埋雷
- 修改 `app/build.gradle.kts` 时注意不破坏现有 version.properties 自动递增逻辑
