# PersonalOvertimeRecord - 个人加班记录应用

一个功能丰富、稳定可靠的Android应用，用于记录个人的加班信息和计算加班工资。

![Version](https://img.shields.io/badge/version-0.2.0-blue)
![Min SDK](https://img.shields.io/badge/minSdk-24-green)
![Target SDK](https://img.shields.io/badge/targetSdk-36-orange)

## 功能特点

### 核心功能
- 📅 **日历视图** - 直观的日历界面展示考勤记录
- 💰 **智能计算** - 自动计算加班时长和加班工资
- 🎚️ **按条自定义倍率** - 每条记录可单独指定工资倍率（1.0x ~ 4.0x），不填则按默认规则计算
- 🎯 **登记即分类** - 登记"加点"按正常工作日（1.5x）、登记"加班"按周末/节假日（2x/3x）计算，不再受日历数据限制
- 📊 **月度统计** - 实时统计当月加班时长、预计工资
- 📈 **月度分析报表** - 支持 ◀/▶ 切换月份，按月查看加班天数、总时长、加班工资与工资构成
- 📊 **堆叠柱状图** - 月度时长柱状图用不同颜色区分"加班"与"加点"
- 🎯 **智能区分** - 工作日、周末、节假日加班倍率自动识别（含调休补班日）
- 🏖️ **请假/早退登记** - 支持 10 种请假类型（年假、病假、事假、婚假、产假等）按天登记，与加班记录同表管理
- 🌗 **白班/夜班标记** - 录入时切换班次（默认白班），列表夜班角标，本月统计按班次拆分
- 🌐 **节假日在线更新** - 内置 2024-2028 节假日与调休补班日，设置页可在线拉取仓库最新数据覆盖内置（校验后本地缓存，离线可用）

### 数据管理
- 📤 **数据导出** - 支持导出为 PDF 精美报告、CSV/JSON 格式
- 📥 **数据导入** - 从文件恢复历史数据
- 🌐 **云端同步** - 支持 WebDAV 协议双向同步（仅 https）
- 🔄 **自动同步** - 后台定时自动同步数据到云端，设备重启后自动恢复调度
- 🔀 **增量同步** - 增量合并后上传完整数据，云端数据不丢失
- 🗑️ **删除同步** - 删除操作可跨设备同步，已删除的记录不会"复活"
- 🔑 **同步恢复码** - 开启同步加密时生成离线恢复码，遗忘密码也能凭码重置，不会因忘密码永久丢数据
- 👥 **团队同步** - 私有服务端多用户同步（JWT 登录 + HTTPS），管理员可建号、重置密码、停用账号并查看按人按月汇总
- 🖥️ **PC 端仪表盘** - PC 读取器用同一套 WebDAV 凭据拉取备份并本地解密，浏览器查看加班统计
- 🗓️ **日历双向同步** - 加班/请假记录同步为系统日历全天日程，支持在日历中改时长、改期与删除，再次同步回写应用

### 用户体验
- 🌙 **深色模式** - 支持跟随系统/浅色/深色三种主题
- ✨ **流畅动画** - 精心设计的过渡动画效果
- 🔐 **生物识别保护** - 通过中转启动页拦截外部启动，主界面不可被外部应用直接拉起
- 📡 **同步进度面板** - 顶部半透明调试面板实时展示同步进程，结束后结果保留 2 秒自动隐藏，可点击面板手动关闭
- 📜 **应用内修改日志** - 设置页离线查看各版本更新内容
- 🙈 **敏感字段脱敏** - WebDAV 服务器地址/用户名默认掩码显示，聚焦编辑时恢复明文；密码支持长按眼睛图标临时查看

### 安全与稳定
- 🔒 **数据加密** - SQLCipher 数据库加密，主密钥由 Android Keystore 保护（不再明文存储）
- 🔐 **隐私存储** - EncryptedSharedPreferences 存储敏感信息
- 🛡️ **健壮性** - 全局异常处理、数据验证机制
- 📡 **网络健壮** - 超时处理、连接测试、标准 SSL 证书校验；禁止明文 HTTP 流量（WebDAV 仅 https）；429/5xx 自动重试
- 🔐 **同步安全** - 信封加密（随机 DEK + 同步密码/恢复码双钥匙，AES-256-GCM，PBKDF2 60 万次派生）；全局互斥锁避免并发同步冲突

```bash
# 克隆项目
git clone https://github.com/Tree-shady/PersonalOvertimeRecord.git

# 进入项目目录
cd PersonalOvertimeRecord

# 同步 Gradle 依赖
./gradlew --refresh-dependencies

# 构建 Debug 版本
./gradlew assembleDebug

# 安装到设备
./gradlew installDebug

# 构建 Release APK（应用内更新通道）
./gradlew assembleRelease

# 构建 Release AAB（应用商店上架）
./gradlew bundleRelease
```

## 功能说明

### 加班计算规则

#### 登记即分类（核心规则）

应用以**登记内容**为准确定当天待遇，不依赖日历数据：

| 登记内容 | 日期分类 | 倍率 |
|---------|---------|------|
| 登记了**加班**（加班时长 > 0） | 视为周末/节假日 | 日历上是法定节假日按 3.0x，否则按 2.0x |
| 只登记了**加点**（加点时长 > 0） | 视为正常工作日 | 1.5x |
| 两者都未登记 | 按日历自动判定 | 工作日 1.5x / 周末 2.0x / 节假日 3.0x |

> 含义:"**加点**"= 正常工作日延长工时(1.5 倍);"**加班**"= 休息日/节假日上班(2/3 倍)。
> 手动登记"加点"或"加班"时即按上表分类计算，无需依赖打卡数据。

#### 按条自定义倍率

默认倍率之外，每条记录可在添加/编辑时单独填写工资倍率（合法范围 1.0 ~ 4.0，留空表示按上表默认规则）：

- 自定义后该条工资 = 时长 × 时薪 × 自定义倍率，不受当天日期分类影响
- 字段为记录级 `customRate`（-1 为"未自定义"哨兵），随 JSON 备份与云端同步往返，老数据自动按默认倍率处理（数据库迁移 6→7）

#### 日历默认倍率(未登记时兜底)

| 日期类型 | 默认倍率 | 说明 |
|---------|---------|------|
| 工作日 | 1.5x | 周一至周五(含调休补班日) |
| 周末 | 2.0x | 周六、周日 |
| 节假日 | 3.0x | 国家法定节假日 |

> 节假日数据内置 2024-2028 年(2024-2026 依据官方安排,2027-2028 为农历预测),并包含 2024/2025 调休补班日(按工作日 1.5 倍计算)。

### 请假/早退登记

在日常考勤中，遇到请假或提前下班（早退）时，可将当天登记为请假记录：

- **登记方式**：添加/编辑记录时打开「请假」开关，选择请假类型与天数
- **请假类型**：年假、病假、事假、婚假、产假、陪产假、丧假、工伤假、无薪假、其他，共 10 种
- **按天登记**：以天为单位（1 天 = 8 小时），天数上限为当月剩余天数
- **数据字段**：`isLeave`（是否请假）、`leaveType`（请假类型）、`leaveHours`（请假天数）
- **与加班互斥**：同一日期要么登记请假、要么登记加班/加点，保存时相互清除

> 说明：请假/早退目前以「登记与展示」为主，不参与加班费计算；如需在工资中扣减请假天数，可在后续版本接入。

### 报表月度分析

报表页面默认展示当前月份，支持按月维度进行分析：

- **月份切换**：顶部 ◀/▶ 按钮切换月份，跨年自动切换年份
- **概览卡片**：按选中月份统计加班天数、总时长、加班工资
- **工资构成**：按选中月份显示底薪、绩效、加班工资、本月工资
- **月度时长柱状图**：全年 12 个月，堆叠展示"加班"（紫色）与"加点"（橙色）时长
- **加班类型分布饼图**：当月工作日/周末/节假日加班时长占比
- **加班工资趋势折线图**：全年 12 个月加班工资变化趋势

### 节假日在线更新

内置节假日数据覆盖 2024-2028，可在设置页「节假日数据」卡片手动检查更新，无需发版即可跟进国家法定节假日与调休安排：

- **数据源** - 仓库固定地址 `holiday/holidays.json`（https）；主源 `raw.githubusercontent.com` 不可达或未发布时，自动依次改用 jsDelivr（cdn/fastly/gcore）镜像读取同一文件
- **兜底接口** - 以上 JSON 源全部失败时，改用第三方接口 `api.apihubs.cn/holiday/get` 拉取当前年与下一年的放假/调休数据，转成同一份 JSON 结构后缓存；接口有频率限制，提示「请求过于频繁」时稍后再试
- **覆盖规则** - 在线数据按日期合并覆盖内置数据（未覆盖的日期继续使用内置），应用启动时从本地缓存注入，离线同样生效
- **校验** - 严格校验日期格式（`yyyy-MM-dd`）、年份范围、节假日名称长度；数据为空或格式非法时拒绝应用并保留当前数据
- **缓存** - 校验通过后写入本地偏好，下次启动直接生效；更新失败只提示，不影响现有计算
- **状态展示** - 卡片显示覆盖年份与数据版本（当前使用内置数据 / 在线数据 vN）

### 系统日历双向同步

把加班/请假记录同步到系统日历，并接收日历侧的修改，实现「录入一次，两处可见」：

- **权限** - 需要 `READ_CALENDAR` / `WRITE_CALENDAR`，设置页点击「立即同步日历」时按需申请
- **写为全天日程** - 每条有效记录写成一个全天事件，标题携带类型与工时（如 `[加班] 加班2h 加点1h ×1.5 夜班`、`[请假] 年假 1天`），描述带固定标记用于识别
- **回写应用** - 同步时优先读取日历：标题中的加班/加点时长、自定义倍率、请假类型与天数回写到应用；在日历中移动日期会改期到新日期；删除事件则同步删除应用记录
- **冲突规则** - 以每条记录上次同步时间（`syncedAt`）为准：应用侧在同步后未再修改时接受日历改动；应用侧有更新改动时以应用为准覆盖日历
- **实践边界** - 映射关系存于本机数据库（数据库 8→9 新增 `calendar_links` 表），不参与云备份与团队同步；同步为手动触发，避免后台写日历
- **结果反馈** - 完成后提示推送、回写、删除与跳过条数，并在卡片展示当前可写日历与上次同步时间

### 云端同步机制

- **双向同步** - 智能合并本地与云端数据，保持两端一致
- **冲突策略** - 支持较新者获胜 / 本地优先 / 云端优先
- **增量合并** - 变更记录与云端现有数据合并为完整备份后上传，云端数据不丢失
- **删除同步** - 基于软删除标记（tombstone），删除操作可跨设备同步
- **自动同步** - WorkManager 周期任务（15 分钟 ~ 24 小时可选），带网络约束（"仅 WiFi" 时 UNMETERED）；任务持久化，设备重启/应用升级后自动恢复，无需开机广播与精确闹钟权限
- **并发保护** - 全局互斥锁，手动与自动同步不会互相覆盖
- **覆盖保护** - 下载/解密失败时中止上传，避免本地数据覆盖式冲掉云端备份
- **失败重试** - WebDAV 上传/下载遇到 408/429/502/503/504 自动退避重试
- **互斥保护** - 团队同步与 WebDAV 同步共用 `SyncGate` 闸门，二者不会并发写同一个数据库

### 团队同步（私有服务端）

面向小团队的多人同步方案（方案 B）：App 登录自建服务端，全量同步 + NEWER_WINS 冲突合并（与本地 `RecordMerge` 语义一致）。

- **登录** - 用户名 + 密码换 JWT（30 天有效），设置页可修改密码、退出登录
- **数据边界** - 只上云加班/请假工时记录（加班费由客户端算好后随记录上传）；薪资、倍率、WebDAV 配置等敏感设置仅存本地
- **管理员** - 建号（密码仅建号时返回一次）、重置成员密码、停用/启用账号、按人按月汇总（加班/请假时长与次数，不含工资）
- **部署** - 单文件 fat jar + systemd，详见 [server/README.md](server/README.md)（含 HTTPS 反代与每日备份策略）
- **互斥** - 与 WebDAV 同步通过 SyncGate 串行，避免并发写库

### PC 端监控（方案 A：WebDAV + PC 读取器）

`pc-monitor/overtime_monitor.py`：用与 App 相同的 WebDAV 凭据拉取云端备份，完全兼容三种云端格式并**本地解密**，浏览器仪表盘展示加班统计（每 60 秒局部刷新，不打断筛选/排序）。

- 口径与 App 一致：法定节假日 3 倍、周末 2 倍、加点 1.5 倍，内置 2024-2028 节假日与调休补班日，支持 `overtimeRateHoliday` 等备份内倍率
- 明细表支持按月份/类型/关键字筛选与按日期/时长排序；`/export.csv` 可导出全量记录（UTF-8 BOM，Excel 直接打开）
- 支持在浏览器中**修改/软删除已有记录**（加班、加点、自定义倍率、备注），写回云端后手机端下次同步即生效；为保护数据，仅允许改/删已有日期，不支持从 PC 新增记录
- 写回安全：每次保存重新拉取最新云端再改一条记录，PUT 带 `If-Match`/`If-Unmodified-Since` 条件（412 自动重试），写前在本机 `backup_history/` 归档原始密文（保留最近 50 份），写后回读解密校验；重封信封时保留原密码槽，恢复码持续有效；旧版 AES-CBC 备份拒绝写回，需先在 App 同步升级
- 写入接口仅接受本机来源（Host/Origin 校验），防 DNS rebinding 与 CSRF
- 可在 `config.json` 配置 `month_target_hours` / `month_target_pay` 显示月度目标进度条；`notify_on_error` 控制拉取失败时的 Windows 通知
- 仪表盘仅绑定 `127.0.0.1`，不向局域网暴露数据；凭据仅发给同注册域主机，拒绝 https→http 降级
- 使用方式详见脚本头部注释（`python overtime_monitor.py`，支持 `--selftest` / `--port` / `--no-browser`）

### 同步加密与恢复码（信封加密）

云端备份采用[信封加密](docs/信封加密恢复码方案实施总结.md)，解决"忘记同步密码即数据永久丢失"的问题：

- **双钥匙结构** - 每次备份由随机生成的 256 位数据密钥（DEK）做 AES-256-GCM 加密；DEK 分别被「同步密码」和「随机恢复码」两份独立秘密包裹（PBKDF2-HmacSHA256 60 万次派生），任一把钥匙都能解开备份
- **恢复码** - 开启加密时生成 80 位熵的 Crockford Base32 恢复码（`XXXX-XXXX-XXXX-XXXX`），仅在本机展示一次，请离线抄写保存；输入容错（忽略大小写、连字符、空格，自动纠正 O/0、I/L/1）
- **遗忘密码找回** - 设置页「用恢复码找回」输入恢复码即可重置同步密码并恢复云端数据，无需卸载重装；找回后立即自动同步——云端密码槽仍由旧密码包裹期间，同步以本地已接入的 DEK 读取云端，上传时自动用新密码重建信封（云端自愈）
- **生物识别查看** - 设置页可经指纹/面容验证后查看当前同步密码与恢复码
- **重装/换机安全** - 在新设备开启加密时先探测云端：云端已有加密备份则接入原 DEK 与恢复槽（**原恢复码持续有效，不会另起密钥谱系**），确认云端无备份才生成新恢复码
- **谱系不变量** - 更换密码、换新设备都只重包密码槽，恢复槽原样复用；只有主动「更换恢复码」才会作废旧码
- **旧版自动迁移** - 历史明文备份与旧版密码直加密文件保持可读，下次同步时自动升级为信封格式
- **性能** - 密码槽本地缓存复用，稳态每次同步仅需一次 PBKDF2 派生

### 软件自动更新机制

- **分发渠道** - 基于 GitHub Releases 分发，`release.yml` 打 tag 时自动生成 `latest.json` 更新清单，并同时上传签名 APK 与 AAB：APK 供应用内自动更新（`latest.json` 指向它），AAB 供 Play Console 等应用商店上架
- **包体差异** - APK 含全部 ABI（arm64-v8a / armeabi-v7a / x86 / x86_64），体积较大；AAB 由商店按设备拆分下发，单机下载体积更小。因此 GitHub 直装包与商店包分开产出，两者不可互换使用
- **渠道签名** - 若商店启用 Play App Signing，商店版会被 Google 用另一把密钥重签，与 GitHub APK 签名不一致，两个渠道的安装包不能互相覆盖安装；如需互通须保持同一签名密钥，或只使用单一分发渠道
- **检查方式** - 启动时静默检查（24 小时节流），设置页可手动"检查更新"
- **更新流程** - 拉取清单 → 比较 versionCode → 下载 APK（带进度）→ SHA-256 校验 → 签名一致性校验 → 调起系统安装器
- **强制更新** - 清单 `minVersionCode` 高于当前版本时弹窗不可取消、无"稍后"按钮
- **安全** - 清单与 APK 均走 https；SHA-256 防篡改；下载包签名与已安装应用不一致时拒绝安装
- **兼容** - Android 8.0+ 通过 `REQUEST_INSTALL_PACKAGES` + FileProvider 调起安装器，未授权时引导用户开启"允许安装未知来源应用"
